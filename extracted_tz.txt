1. Общие сведения
1.1. Наименование и назначение
Полное наименование: «Локальный планировщик проектов» (LocalPM). Краткое наименование: LocalPM.
Назначение: автономный (offline-first) инструмент календарно-сетевого планирования для одного пользователя,
позволяющий вести несколько проектов с задачами, вехами, группировкой, связями и диаграммой Ганта, хранить
все данные локально на устройстве и переносить рабочее пространство между устройствами без установки и без
сервера.
Ключевое решение версии 2.0: продукт поставляется как статическое веб-приложение (один каталог с файлом
index.html и ресурсами) и запускается в любом современном браузере. Вся логика, расчёты, импорт и экспорт
выполняются в браузере; серверная часть (Python, база данных на сервере, администрирование) отсутствует.

1.2. Термины и сокращения
Термин
Определение
Проект
Совокупность задач, вех, связей и настроек календаря с общей датой начала.
Задача (task)
Элемент работ с длительностью, датами начала/окончания и примечанием.
Веха (milestone)
Задача нулевой длительности, отмечающая значимое событие (точку контроля).
Суммарная задача
Строка-группа (фаза/этап), агрегирующая дочерние задачи по WBS-иерархии.
WBS
Work Breakdown Structure — иерархическая структура работ (уровень вложенности задачи).
Связь (dependency)
Ограничение порядка выполнения между задачами (FS, SS, FF, SF) с лагом.
Лаг
Смещение между связанными задачами в рабочих днях (положительное или отрицательное).
Критический путь
Цепочка задач, задержка любой из которых сдвигает дату окончания проекта.
Диаграмма Ганта
Графическое представление плана: таблица задач + временная шкала с полосами.
Рабочий календарь
Набор рабочих дней недели и список исключений (праздники).
Рабочее пространство
Совокупность всех проектов пользователя и глобальных настроек на устройстве.
PWA
Progressive Web App — веб-приложение, устанавливаемое на устройство, работающее офлайн и
сохраняющее данные локально.
Serverless / клиентское
приложение
Приложение без серверной части: логика исполняется в браузере, данные хранятся на устройстве.
IndexedDB
Встроенная в браузер транзакционная база данных для хранения данных приложения.
OPFS
Origin Private File System — приватное файловое хранилище браузера (запасной уровень хранения).
Persistent Storage
Режим «постоянного» хранилища браузера, защищающий данные от автоматической очистки.
MVP
Минимально жизнеспособный продукт (первая поставляемая версия).

2. Основание для разработки и цели
2.1. Проблема
  Microsoft Project — десктопный продукт с платной подпиской, привязанный к Windows; не работает на Android, не
переносится простым копированием, избыточен для одного пользователя.
 Облачные трекеры требуют постоянного подключения к сети и передают данные третьим лицам.
 Планы в Excel не дают наглядной диаграммы Ганта, связей и автоматического пересчёта дат.
 Десктопные приложения требуют установки, обновления и переноса зависимостей, что противоречит
требованию «легко переносится между компьютерами».
2.2. Цели
 1. Дать пользователю рабочее пространство со всеми проектами, переносимое копированием одного каталога или
одного файла экспорта.
2. Обеспечить полный offline-режим на Windows, Linux, macOS и Android без установки программы и без сервера.
3. Воспроизвести ключевой функционал MS Project, реально используемый одним планировщиком: задачи, вехи,
WBS-группировка, связи 4 типов с лагами, диаграмма Ганта, критический путь.
4. Ускорить ввод плана: массовая вставка задач из Excel, копирование/вставка блоков строк.
5. Обеспечить выдачу результата в PDF (через печать браузера) и Excel (XLSX) для отчётности.
6. Обеспечить передачу проекта другому пользователю файлом и возврат изменений автору без сервера и учётных
записей.

2.3. Целевая аудитория и контекст использования
Роль
Сценарий использования
Планировщик / РП (основной)
Ежедневно/еженедельно ведёт 3–10 личных проектов на ноутбуке.
Планировщик в дороге
Просматривает и корректирует план на Android-планшете/телефоне без интернета.
Руководитель / заказчик
Получает PDF-план и не редактирует его.
Коллега
Получает XLSX-выгрузку для сведения или согласования.
Коллега-исполнитель
Получает копию проекта файлом *.lpmproject, работает со своей копией и при необходимости
возвращает изменения автору.
2.4. Границы проекта
Входит в объём работ:
  Клиентское веб-приложение (PWA): HTML/CSS/JS, диаграмма Ганта на Canvas, работа офлайн.
 Хранение данных на устройстве (IndexedDB + постоянное хранилище), экспорт/импорт файла проекта *.lpm.json.
 Импорт XLSX/CSV/буфера обмена средствами браузера, экспорт XLSX, экспорт PDF через печать браузера.
 Инструкция по переносу и работе на Android.
 Передача проекта другому пользователю: файл *.lpmproject, импорт с предпросмотром, журнал передачи,
возврат изменений со сравнением версий.
Не входит в объём работ (см. п. 3.3):
  Серверная часть, база данных на сервере, административная панель, установка программного обеспечения.
 Многопользовательская работа в реальном времени, роли и права, синхронизация через сеть, автоматическое
слияние версий.
 Учёт ресурсов и трудозатрат, выравнивание ресурсов, бюджетирование.
 Обмен в формате MPP/MS Project; облачные сервисы.
 Нативные мобильные приложения (Android/iOS) — вместо них PWA.

4.14. Расчёт расписания (CPM)
Расчёт выполняется в браузере отдельным модулем и не зависит от сервера. При любом изменении структуры,
длительностей, связей, календаря или флагов автопланирования выполняется пересчёт:
 1. Прямой проход: раннее начало (ES) и раннее окончание (EF) по всем связям с учётом типа и лага.
2. Обратный проход: позднее начало/окончание (LS/LF) от даты окончания проекта.
3. Резерв (Total Float) = LS − ES; задача критична, если резерв ≤ 0.
4. Суммарные задачи агрегируются из дочерних (min/max дат, сумма работ не дублируется).
5. Расчёт выполняется в Web Worker, чтобы интерфейс не «подвисал» на планах до 5 000 задач.
Правила: связи считаются в рабочих днях календаря проекта; при конфликте связей и фиксированных дат приоритет
у фиксированных дат с предупреждением; алгоритм обнаруживает циклы и останавливает расчёт с указанием
цепочки.
4.14.1. Формальные правила планирования
Тип связи
Ограничение (в рабочих днях)

6.1. Архитектура: статическое PWA без сервера
Браузер (ПК / Android)
  ├── index.html + app.js (UI, сетка задач, диаграмма Ганта)
  ├── cpm-worker.js   — расчёт расписания в Web Worker
  ├── sheetjs + file-saver — импорт/экспорт XLSX
  ├── print.css      — печатный шаблон для PDF через печать браузера
  ├── manifest.webmanifest + service-worker.js — установка PWA, офлайн-кэш
  └── IndexedDB (localpm) — рабочее пространство на устройстве
          ├── projects / tasks / dependencies / calendars
          └── settings / change_log / schema_version
 
Перенос и резервная копия — файл *.lpm.json (экспорт/импорт)
Обоснование «почему веб-приложение»:
  Переносимость: каталог статических файлов запускается в любом браузере без установки, копируется на флешку,
работает у любого пользователя без Python и административных прав.
 Android: PWA устанавливается на главный экран, работает офлайн, открывает файлы системным диалогом и
печатает в PDF — без Termux и терминала.
 Единая кодовая база и одинаковое поведение на ПК и телефоне; обновление — заменой статических файлов.
 Данные остаются локальными: нет сетевых сервисов, нет передачи информации третьим лицам.

6.4. Формат файла проекта и резервной копии (*.lpm.json)
{
  "format": "localpm",
  "formatVersion": 1,
  "exportedAt": "2026-10-22T12:00:00Z",
  "scope": "project" | "workspace",
  "projects": [ { ...проект, tasks: [...], dependencies: [...], calendar: {...} } ],
  "settings": { ... },
  "checksum": "sha-256 от сериализованного содержимого"
}
Файл читается и записывается браузером; при импорте контролируется checksum и версия формата, несовместимые
версии отклоняются с сообщением.
6.5. Формат пакета передачи проекта (*.lpmproject)
Пакет передачи — отдельный формат (не резервная копия), содержащий ровно один проект (или предложение
изменений при возврате). Структура — JSON с метаданными передачи; расширение позволяет отличить передачу от
бэкапа и отобразить в имени файла проект и дату.
{
  "format": "localpm-project-package",
  "formatVersion": 1,
  "kind": "transfer" | "return",          // передача проекта или возврат изменений
  "packageId": "uuid",
  "createdAt": "2026-10-22T12:00:00Z",
  "sender": { "name": "Иванов И.И.", "organization": "..." },
  "recipient": { "name": "Петров П.П." },
  "comment": "План на согласование",
  "project": {
    "projectId": "uuid проекта-источника",
    "name": "План внедрения",
    "revision": 7,
    "baseRevision": 5,             // для kind=return: версия на момент передачи
    "changedAt": "2026-10-22T11:40:00Z",
    "author": "Иванов И.И.",
    "calendar": {...},
    "tasks": [ {...} ],
    "dependencies": [ {...} ]
  },
  "includeHistory": false,        // FR-17.12: без истории и журнала
  "cipher": null | { "alg": "AES-GCM", "salt": "...", "iv": "..." },
  "checksum": "sha-256 от project и метаданных (Web Crypto API)"
}
Правила обработки:
  Импорт отклоняется, если не совпадает format/formatVersion, не подтверждена контрольная сумма или
отсутствуют обязательные поля.
 kind = transfer: проект всегда импортируется как новая независимая запись; поле origin_id = projectId.
 kind = return: ищется проект с совпадающим projectId; при наличии — экран сравнения и выбор «Принять /
Отклонить»; при отсутствии — импорт как новая копия с отметкой о возврате.
 Текст из пакета не интерпретируется как HTML или формулы (FR-17.10).

Только open-source библиотеки с лицензиями MIT/BSD/Apache; материалы MS Project не используются;
