## 4. Архитектура и запуск
- Статический каталог; запуск открытием `index.html`, мини-сервером (`start.cmd`, http://localhost) или с носителя; без админ-прав, служб, реестра.
- Модули (логические): ui (экраны/сетка/карточка), gantt (Canvas+виртуализация), cpm (расчёт), storage (IndexedDB+FS Access+файл-БД+миграции), io (tsv/csv/xlsx-export/transfer), print (печать/PNG), sw+manifest (PWA, отдельные файлы каталога).
- Режимы БД при старте (по приоритету): (а) сохранённый в IndexedDB.meta `FileSystemFileHandle` с разрешением → режим `file` (автосохранение, дебаунс 700 мс); (б) `fetch('./localpm-data.json?_=ts')` → режим `fetch` (чтение из папки приложения); (в) иначе режим `local` + флаг dbMissing.
- D-10: при dbMissing — модальный диалог «База данных не найдена» (путь `./localpm-data.json`): «Создать БД в папке…» (showSaveFilePicker, suggestedName; фолбэк — скачивание шаблона; опция «с демо-проектом»), «Выбрать файл БД…» (showOpenFilePicker/input[file]), «Скачать шаблон БД», «Работать локально (без файла)» (флаг в sessionStorage), «Повторить проверку». Повторный fetch при возврате на вкладку (visibilitychange) с предложением загрузить найденный файл.
- Индикатор БД в шапке: путь, режим, грязность («синхронно / сохранение… / есть несохранённые / не найдена — локально»); клик — модалка БД (статус Persistent Storage через `navigator.storage.persisted()`, время сохранения, кнопки открыть/подключить/создать/обновить/резервная копия/экспорт-импорт WP/сохранить).
- Конфликт версий: локальное зеркало новее файла >1.5 с → диалог «взять из файла / оставить локальную и записать».
- Кнопка «💾 Сохранить» и Ctrl+S (D-09): запись в handle, иначе скачивание localpm-data.json с подсказкой. beforeunload-предупреждение при грязной БД вне режима file.

## 6. Форматы файлов
### 6.1 База / рабочее пространство / бэкап (`localpm-data.json`, `*.lpm.json`, `localpm-backup-YYYY-MM-DD.json`, `localpm-workspace-*.json`)
```json
{ "format":"localpm", "formatVersion":1, "schemaVersion":2,
  "scope":"workspace", "dataKind":"database", "exportedAt":"ISO",
  "projects":[ project ], "settings":{ "theme", "owners":[str], "userName" } }
```
Миграция (FR-4.06): schemaVersion > текущей → отказ с сообщением; < текущей → миграция с донаполнением полей и пометкой migratedFrom. Импорт WP: режимы «добавить» (коллизиия id → новый id) / «заменить» (с резервной копией).
### 6.2 Пакет передачи `<Название>_<ГГГГ-ММ-ДД>.lpmproject`
```json
{ "format":"localpm-project-package", "formatVersion":1, "kind":"transfer"|"return",
  "packageId":"uuid", "createdAt":"ISO",
  "sender":{"name","organization?"}, "recipient":{"name"}, "comment":"≤1000",
  "includeHistory":bool, "cipher":null,
  "project":{ "projectId","name","revision","baseRevision","changedAt","author",
              "description","start_date","status_date","view_settings","custom_fields",
              "calendar":{"calendar_id","working_days","exceptions"},
              "tasks":[], "dependencies":[] },
  "checksum":"sha256( JSON(project)+JSON(sender)+JSON(recipient)+comment+kind )" }
```
Правила: несовпадение format/checksum → отказ без изменения рабочего пространства; kind=transfer → новая независимая запись (origin_id=projectId; суффикс имени «(передан от X)» при коллизии projectId); kind=return → поиск по projectId → экран сравнения (добавлено/изменено/удалено по полям name,duration,start,finish,percent,owner,note) → «Принять» (бэкап прежней версии + запись в transferLog) / «Отклонить» (запись в журнал); если источник менялся после передачи (revision > baseRevision) — предупреждение с датой и версией (FR-17.13); возврат без источника → копия с отметкой «Возврат от…». Перед формированием — валидация плана: циклы блокируют/требуют подтверждения со списком проблем (FR-17.04). «Чистый» режим без истории (FR-17.12). Текст из пакетов не интерпретируется как HTML/формулы (FR-17.10).

## 7. Календарь и время
- Серийные рабочие дни 2000-01-01…2060-12-31; кэш `{dateToSerial, serialToDate}` на проект по сигнатуре (calendar_id, working_days, exceptions); инвалидация при смене настроек.
- Рабочий день = dow ∈ working_days И ∉ exceptions И НЕ (calendar_id='rf' И праздник РФ). Праздники РФ фиксированные без переносов: 1–8.01, 23.02, 8.03, 1.05, 9.05, 12.06, 4.11 ежегодно (до 2060).
- ensureWorkday(date) — ближайший рабочий вперёд; ввод/импорт нерабочей даты приводится к рабочему дню.
- Длительности: `д`/без суффикса = раб. дни, `н` = ×5, `ч` = ceil(ч/8). Форматы ввода дат: ДД.ММ.ГГГГ, ГГГГ-ММ-ДД, ДД.ММ (текущий год).

## 8. Расчёт расписания (CPM)
Формулы (рабочие дни, серийные индексы): FS: ES(B) ≥ EF(A)+lag+1; SS: ES(B) ≥ ES(A)+lag; FF: EF(B) ≥ EF(A)+lag; SF: EF(B) ≥ ES(A)+lag; EF = ES+dur−1; веха: dur=0, EF=ES.
```
expand: связи с succ-суммарной развернуть в ограничения на все листовые потомки succ (тот же type/lag)
for pass in 1..2:                     # суммарные-предшественники уточняются итеративно
  topo = Kahn(листовые); неполный topo → p.cpmError + дообход в порядке дерева
  forward: ES = max( базовое start_date | start проекта,
                    кандидаты входящих связей (pred — лист или суммарная из summaryCalc),
                    serial(constraint_snet) );
           is_manual: ES/EF фиксированы; кандидат > ES → scheduleWarnings (FR-12.01)
           EF по формуле длительности
  aggregate bottom-up: суммарные (кроме is_manual): start=min детей, finish=max детей,
           dur = finish−start+1 серийных, percent = взвешенный по длительности (вехи — среднее),
           critical = OR детей; is_manual-суммарные сохраняют свои даты (D-02/R2-03)
backward: LF = EF проекта; релаксация по исходящим (FS/FF по LF; SS/SF через LS+offset);
          float = LS−ES; critical = float ≤ 0
запись в листы (кроме manual): start/finish/duration; суммарным — критичность и даты агрегации
project: finish = max finish; percent = взвешенный; updatedAt = now
```
Ручной режим: даты не переписываются; ✋ в сетке, оранжевый контур полосы; конфликты — в scheduleWarnings и статусную строку. Кнопки «Автоплан»/«Ручной план» применяют режим к выделению (D-08; по умолчанию все задачи автоматические).

## 11. Диаграмма Ганта
- Композиция «таблица+шкала» с синхронной вертикальной прокруткой; перетаскиваемая граница панелей.
- Шашка 2 уровня (месяц/год + дни или месяцы); подсветка выходных/праздников календаря проекта; линия «сегодня».
- Полосы: задача — скруглённый прямоугольник (критическая красная), прогресс-заливка по % (флаг showProgress), ручной режим — оранжевый контур; веха — ромб радиусом clamp(4..9, px/день*0.45) с центром по дате, крепления связей — вершины ромба (±r); суммарная — скобка; базовый план — тонкая серая линия под полосой; подписи на полосах при showLabels.
- Связи: ортогональные линии со стрелкой; SS — пунктир; лаг подписью «+2д»; критическая цепочка — красным; флаг showDeps.
- Виртуализация: рисуются только видимые строки (по scrollTop), холст sticky; ширина таймлайна полная с лимитом 30000 px (автоуплотнение px/день); Ctrl+колесо — масштаб.
- Клик/dblclick по полосе — выделение/карточка. Экспорт PNG (Canvas 2×, полная высота). Печать/PDF: печатная область (титул, сводка, план, вехи, Гант-PNG 2× с легендой), @page A4 landscape, разрывы страниц, повтор заголовков, кириллица системными шрифтами, колонтитул «Подготовлено в LocalPM».

## 12. Импорт
Источники: вставка TSV/CSV текстом, файл .csv/.txt/.tsv (≤10 МБ, ≤5000 строк), системный диалог на Android. XLSX — только при подключённом локальном SheetJS (window.XLSX), иначе сообщение (отклонение, раздел 19).
Мастер: предпросмотр 20 строк; автоопределение заголовков (таблица алиасов ниже + имена пользовательских полей + «ответственный/владелец/owner» + «уровень/level» + «статус/% завершения»); ручное пересопоставление селектами; режимы «добавить»/«заменить» (с резервной копией); позиция «в конец / после выбранной / в поддерево выбранной»; иерархия по колонке «Уровень».
Алиасы заголовков (FR-5.05): №/Номер/ID/Код/WBS/Код задачи; Задача/Название/Наименование/Работа/Task/Name/Описание; Длительность/Длит./Duration/Срок; Начало/Дата начала/Start/Начало работ; Окончание/Дата окончания/Finish/Конец/Завершение; Примечание/Комментарий/Note/Notes/Заметка; Предшественники/Связи/Predecessors/Зависимости; Веха/Milestone/Контрольная точка; Уровень/WBS/Level/Иерархия; Ответственный/Владелец/Owner; Статус/Процент завершения/% готовности/% выполнения.
Правила: длительность из суффиксов; только даты → длительность; только длительность+начало → окончание по календарю; окончание<начала → строка пропускается с причиной; дубли «№» — предупреждение (внешний код разрешён); связь на несуществующий номер — предупреждение, строка импортируется; веха с dur>0 → dur=0 с предупреждением; dur=0 без флага → веха; связи в синтаксисе MSP (`3`, `3,5`, `3НС+2д`, `8ОО-1д`, разделители `,`/`;`), циклы отклоняются с указанием; отчёт импорта (добавлено / пропущено с причинами / предупреждения, ≤10 строк каждого списка + счётчики). Round-trip: заголовки экспорта LocalPM распознаются как шаблон (FR-5.13).
Синтаксис связей (FR-10.01/4.10.1): русские аббревиатуры НС=FS, НН=SS, ОО=FF, НО=SF; лаг `+Nд`/`−Nд`; комбинации через `,`/`;`.

## 13. Экспорт
- XLSX формируется полностью в браузере (собственный ZIP-store + CRC32 + OOXML inlineStr; числа как `<v>`): листы «План» (№, Задача с отступом, Длительность, Начало, Окончание, Примечание, Предшественники, Веха, %, Ответственный, custom*), «Вехи», «Связи» (A,B,тип,лаг), «Сводка» (показатели + рабочие дни по месяцам). Экранирование формул и CSV-кавычек. Фолбэк без XLSX-движка — CSV с BOM и `;`.
- PDF — печать браузера из печатной области (раздел 11). PNG — Canvas 2×. JSON — проект/рабочее пространство/бэкап (раздел 6).

## 14. Передача и возврат
См. формат 6.2 и правила: журнал передачи в карточке проекта; «Полученные пакеты» в реестре; предпросмотр без вставки (метаданные, счётчики, комментарий, diff для возврата); drag&drop файла .lpmproject/.json на окно с автораспознаванием типа (база vs пакет) и проверкой checksum; состояния и переходы по таблице FR-17.1 (исходный → пакет → копия → пакет возврата → принятие/отклонение с бэкапом).

## 15. Хранение, целостность, журнал
- IndexedDB `localpm` v2: stores `projects(keyPath id)`, `meta(keyPath key)` (fileHandle, last_backup_at). Фолбэк без IndexedDB — localStorage. Запрос Persistent Storage при старте + показ статуса (FR-4.02).
- Автосохранение каждого действия (revision++, updatedAt); при подключённом файле — дебаунс-запись 700 мс.
- Repair при загрузке каждого проекта (FR-4.07): уникальность id; parent≠self/существующий; разрыв циклов дерева; нормализация дат/длительностей/вех; очистка битых и дублирующих связей; удаление циклов связей; нормализация sort_order; пересчёт номеров; отчёт через cpmError/scheduleWarnings/валидатор.
- Валидатор «Проблемы плана» (FR-4.13): нет предшественников/последователей у листовой; окончание в прошлом при %<100 и не manual; конфликты ручных дат; циклы с цепочкой.
- changeLog проекта: записи при создании/удалении/перемещении/indent/outdent/правке/импорте/вставке/группе; показ в карточке (D-14).
- Архив: удаление → archived+archivedAt; восстановление; автоочистка >30 дней при загрузке (FR-2.08).
- Резервные копии: «Создать резервную копию» → localpm-backup-YYYY-MM-DD.json; автобэкап перед миграцией схемы и перед заменой проекта/WP (FR-4.05).

## 16. Граничные случаи (обязательное поведение)
| Случай | Поведение |
|---|---|
| Длительность 0 без флага вехи | флаг «Веха» + предупреждение |
| Веха с dur>0 (импорт/правка) | dur→0 + предупреждение |
| Окончание раньше начала | ошибка, откат правки / пропуск строки импорта с причиной |
| Пустое имя | ошибка, откат |
| Цикл связей | сохранение/связь отклоняются, путь/длина цепочки в сообщении |
| Удаление задачи с последователями | связи удаляются, подтверждение с количеством |
| Суммарная с ручными датами | агрегация пропускается, ✋, предупреждения по детям не генерируются |
| Ручные даты против связей | даты сохраняются, warning в статусной строке и валидаторе |
| Indent без одноуровневой строки сверху | notice «шаг всегда +1», структура не меняется (без перескоков уровней) |
| Drag на уровень глубже rowAbove+1 | клампинг до rowAbove+1 (без «дырок» и перескоков) |
| Структурные правки при фильтре/группировке | блокируются с notice |
| Dblclick после клика по строке | редактор открывается (рендер только при смене выделения) |
| БД не найдена при старте | диалог создать/выбрать/шаблон/локально/повторить |
| Файл базы новее/старее локального зеркала | диалог конфликта версий |
| schemaVersion файла > версии приложения | отказ загрузки с сообщением |
| Пакет с битой checksum | отказ, рабочее пространство не меняется |
| Возврат без проекта-источника | импорт копией с отметкой «Возврат от…» |
| Источник менялся после передачи | предупреждение с датой и ревизией перед принятием |
| HTML/формулы в тексте | отображаются как текст; экранирование в XLSX/CSV |
| Квота/память | лимиты импорта; сообщение с предложением выгрузить файл и очистить архив |
| Задача без начала и окончания | начало = дата начала проекта или окончание предшественника |
| Двойная нумерация «№» | разрешена как внешний код; внутренний id уникален; дубликат — предупреждение |
| Пересчёт при выключенном автопланировании | кнопка «Пересчитать план» (автоплан/ручной) |
| Повторное открытие после экспорта | дата последнего экспорта/сохранения в индикаторе БД |

## 17. Нефункциональные требования
Открытие 2000 задач ≤1.5 с; CPM 5000 задач ≤1 с (синхронно, отклонение от Web Worker зафиксировано); прокрутка Ганта ≥30 fps (виртуализация); импорт 1000 строк ≤3 с; передача/возврат ≤3 с; офлайн после первой загрузки; русский UI, даты ДД.ММ.ГГГГ; клавиатурная доступность и зоны ≥44 px; только open-source/собственный код, без CDN; CSP-совместимость; атомарность импорта пакетов.

## 18. Программа испытаний
Встроенный раннер (кнопка «Тесты», печать протокола в PDF): ≥47 проверок, включая: календарь РФ (04.11 нерабочий); «2н»=10; FS+2д → ES(B)=EF(A)+3; веха после предшественника; manual-даты не пересчитываются; уровень 3 существует; перемещение не меняет уровень 3; попытка уровня 6 клампится; цикл обнаруживается; агрегация суммарной; суммарная с manual-датами сохраняется; справочник ответственных пополняется; синтаксис «1НС» и отказ «99НС»; TSV-парсер; XLSX-zip формируется; schemaVersion=2; отказ схемы 99; undo-снапшот; changeLog пишется; SHA-256 доступен; валидатор возвращает массив.
Приёмочные проверки AT-01…AT-20 — по ТЗ ред. 2.1 (запуск без установки; PWA Android; вставка 200 строк TSV; импорт XLSX с «3НС+2д»; ручные операции WBS; веха-ромб и CPM; Гант/связи/критпуть/масштабы; цикл отклоняется; PDF с кириллицей; XLSX round-trip; 5000 задач; офлайн без внешних запросов; мультипроектность; перенос WP; переживание очистки кэша; передача коллеге; повторный импорт того же project_id; битая checksum; возврат с принятием/отклонением и бэкапом; передача при ошибках плана). Дополнения ред. 2.3: AT-21 БД в каталоге подхватывается, при отсутствии — диалог; AT-22 inline-правка всех полей включая суммарные; AT-23 шаг вложенности строго +1; AT-24 групповые ↑/↓/уровень; AT-25 протокол автотестов и его печать.

## 19. Отклонения (зафиксированы и приняты)
1) Импорт XLSX без локального vendor SheetJS не выполняется (компенсация: мастер CSV/TSV + round-trip CSV); vendor поставляется в каталоге. 2) CPM синхронный (без Web Worker). 3) manifest.webmanifest/sw.js — отдельные файлы каталога, не встраиваются в index.html. 4) AES-защита пакетов (FR-17.11) и MSPDI — не реализованы. 5) Drag полос/краёв Ганта (FR-9.08) — не реализован (drag строк реализован).
